# Gouly controller protocol

Reference for the single-output GOULY controller, observed on firmware V50 and V55
with Tuya protocol 3.4. The Gouly Pro uses a different command set, documented by
[ha-gouly](https://github.com/mikemaat/ha-gouly/blob/main/docs/PROTOCOL.md).

## Transport

The controller is a Tuya Wi-Fi module on TCP port 6668. Firmware V50 and V55 use Tuya
protocol 3.4; the plugin also tries 3.5 and 3.3 automatically if 3.4 is rejected. It does not answer Tuya's
UDP discovery, so it has to be found by scanning for port 6668 and trying the key.

| DP | Type | Use |
|---|---|---|
| 20 | bool | Power (mirrors the `F1` command) |
| 101 | raw (base64) | Gouly frames, both directions |

## Frames

```
<header> <command> <payload...> <crc>
```

- header `AA`: a command. The controller **echoes every command it accepts**, whoever
  sent it, so the Gouly app's commands can be observed by any connected client.
- header `BB`: a report generated by the controller.
- crc: CRC-8/MAXIM (reflected polynomial `0x8C`) over all preceding bytes.
- Short commands are zero-padded to 11 bytes including header and CRC.

## Commands

| Command | Payload | Meaning |
|---|---|---|
| `F1` | `01` / `00` | Power on / off |
| `F3` | `vv` | Brightness, `00`-`FF` (the app's 0-100 %). `00` is dimmest, not off |
| `F2` | `R G B W` | Solid color. W is the warm white LED. The app's "CW" is `FF FF FF 00`, "PW" is `FF FF FF FF`, "WW" is `00 00 00 FF` |
| `F6` | see below | Pattern |
| `E5` | none | Sent by the app after every change; changes work without it |
| `FC` | none | State query; the controller answers `BB FC` |
| `EE` | clock and location | Sent by the app on connect; used for sunrise/sunset schedules |
| `EF` | none | Sent by the app after `EE`; purpose unknown |
| `F8` | `hi lo` | Pixel count |
| `FA` | `nn` | LED IC type (`03` = UCS2904) |
| `F7` | `nn` | RGB order (`00` = RGB) |
| `E1` | none | List schedules; one 114-byte `BB E1` record per schedule |
| `FD` | schedule | Write a schedule |
| `E6` | `nn` | Delete schedule `nn` |

### Pattern (`F6`)

```
F6 fx speed b4 dir b6 count  bgR bgG bgB bgW  count x (R G B W)
```

Length is `13 + 4 x count` bytes including header and CRC; pattern frames are not padded.

| Field | Values |
|---|---|
| `fx` | Effect: position in the app's effect list. `01` Static, `02` Breathing, `03` Gradual, `04` Follow, `05` Scroll, `06` Stream, `07` Encircle, `08` Star, `09` Layer, `0A` Phantom, `0B` Pixel Chase, `0C` Undulation, `0D` Multi Pulse, `0E` Expanse, `0F` Spectrum, `10` Spotlight, `11` Flicker, `12` Glitch, `13` Burst, `14` Drift, `15` Sync Fade, `19` Roll, `1A` Extend, `1B` Flame. `16`-`18` are not offered by the app and do not render usefully |
| `speed` | 1-10 (the app's default is 5) |
| `b4` | `00`; `01` for Sync Fade |
| `dir` | `00` Right, `01` Left, `02` Center to Sides, `03` Sides to Center, `04` Elastic Loop. For Sync Fade it is a duty cycle: high nibble LEDs on (1-3), low nibble LEDs off (1-5), for example `23` = 2 on, 3 off |
| `b6` | Pattern brightness; the app always sends `FF` |
| `count` | Number of colors, 1-15 |
| background | RGBW color between lit pixels |
| colors | The repeating pixel sequence, RGBW each |

#### Directions offered per effect

The app offers different motion options per effect. Other values may be accepted by the
controller but are never produced by the app.

| Effects | Directions |
|---|---|
| Static, Breathing, Gradual, Star, Layer, Undulation, Multi Pulse, Spectrum, Spotlight, Flicker, Glitch, Drift, Roll | Right only |
| Expanse, Extend | Right, Left |
| Follow, Scroll, Stream, Encircle, Phantom, Pixel Chase, Burst, Flame | All five |
| Sync Fade | Duty cycle (15 on/off combinations) |

The pixel count (`F8`) determines where "center" is and how long motion takes to
cross the string, so it should match the real number of pixels.

### State report (`BB FC`)

```
BB FC on bri speed 00 pixels(2) 01 icType 01 rgbOrder 01 07 00 13 00 crc
```

`speed` is the speed of the last pattern applied. The trailing bytes have not changed
in any observed state.

### Clock and location (`EE`)

```
AA EE yyyy(2) mm dd hh mm ss 00 latSign lat*100(2) lonSign lon*100(2) tzSign tzHours crc
```

The reply `BB EE 00 05 00 5F 00 37 ...` carries the firmware version (`37` = V55).

### Schedules

Each `BB E1` record holds the slot, an enabled flag, a days bitmask, start and end
month/day/hour/minute, a flag (`20` for sunset-based timers), a 12-byte name and a
complete pattern in the `F6` layout above. Firmware updates go over Bluetooth, not Wi-Fi.
